# 两个对话分工指南

Codex 与 Claude Code 共用。由 `{{GUIDES_DIR}}/AGENTS.md` 指向；只在主对话与执行对话配合时读。

分工：主对话走研究主线，负责定目标、裁决结果、做分析。执行对话负责把一个实验从准备做到结果取回并核验；怎么做、怎么调试、怎么重试、中途找用户批什么，都是执行对话自己的事。适合长时间运行的实验，例如集群上的训练、大批量评测或计算。

## 终点

- 一个任务的终点是：计划中的数据或结果已取回并核验，可以做研究解读。负结果、方法本身跑不通，也算终点。
- 这些都不是终点：准备好的代码或方案、小规模验证、作业提交成功、因为我们自己的脚本或工具出错而没得到结果。
- 中途需要用户批准时，执行对话直接问用户，批准后接着做到终点；任务不因此拆成“先准备、再执行”两段。

## 主对话

- 一次派到终点：给出目标、终点、边界和已有材料。不把准备、验证、修复拆成单独的任务，不要求中途回报，不代用户审批执行事项，不替执行对话派审阅代理。
- 收到结果再读、再裁决、再分析。要改做法时作为新任务整体发出。
- 不接收运行细节。作业号、耗时、资源用量、检查计数留在执行对话的文件里。

## 执行对话

- 按常设授权文件执行；授权之外的事直接问用户，不经主对话转达。
- 给主对话的消息只有两种，开头写明类型：「终点结果」，或「需要研究决定」（方法定不了的研究歧义，或结果改变了研究计划）。两种都不是就不发，写进自己的记录。
- 「终点结果」只写：这是什么、多少、和上次比变了什么、还有什么没解决，外加结果的固定路径。不抄正文，也不抄状态明细。
- 原始数据按原样保留，派生结果另存并写明方法；不替主对话挑选、平均或改写数据。
- 审阅、试错、失败和重试都在自己对话里完成；子代理数量到上限时等已有的结束，不找主对话代派。

## 记录与共用文件

- 执行对话自己写执行记录和“状态与结果入口”（一页，写当前状态和结果的固定路径）；在按工作区规范组织的项目里，这就是它的任务文件夹和其中的 README。主对话写研究决定和 `START_HERE.md`。两边都读入口文件，不为让对方更新记录而发消息。
- 常设授权书：执行对话可以自己做什么、什么必须问用户。由用户定，放在项目的 `docs/AUTHORIZATION.md`。模板：`{{GUIDES_DIR}}/AUTHORIZATION_TEMPLATE.md`。
