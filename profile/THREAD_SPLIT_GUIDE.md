# 两个对话分工指南

Codex 与 Claude Code 共用。两个对话分担一个项目时读。

主对话走研究主线：定目标、裁决结果、做分析。执行对话把一个任务从准备做到结果取回并核验；怎么做、怎么调试、怎么重试、中途找用户批什么，都是执行对话自己的事。适合长时间运行的实验，例如集群上的训练、大批量评测或计算。

## 终点

- 终点是计划中的数据或结果已取回并核验，可以做研究解读。负结果、方法本身走不通，也算终点。
- 准备好的代码或方案、小规模验证、作业提交成功、因为自己的脚本或工具出错而没拿到结果，都不是终点。

## 主对话

- 一次派到终点：给目标、终点、边界和已有材料。不把准备、验证、修复拆成单独任务，不要求中途回报，不代用户审批，不替执行对话派评审。
- 收到终点结果再裁决和分析；要改做法，作为新任务整体发出。

## 执行对话

- 按项目的常设授权文件执行；授权之外的事直接问用户，批准后接着做到终点。
- 给主对话的消息只有两种，开头写明类型：「终点结果」（是什么、多少、和上次比变了什么、还有什么没解决、结果的固定路径），或「需要研究决定」（方法定不了的研究歧义，或结果改变了研究计划）。其余写进自己的记录，不发。
- 发消息前先把原文写进自己的任务文件夹（README 的结果部分或 `messages/`），消息里带上路径。
- 原始数据按原样保留，派生结果另存并写明方法，不替主对话挑选、平均或改写。
- 评审、试错和重试都在自己对话里完成。

## 记录

- 执行对话写自己的任务文件夹和 README（当前状态、结果的固定路径）；主对话写研究决定和 `START_HERE.md`。两边读对方的入口，不为让对方更新记录而发消息。
- 常设授权书由用户定，放在项目的 `docs/AUTHORIZATION.md`；模板见 `{{GUIDES_DIR}}/AUTHORIZATION_TEMPLATE.md`。
