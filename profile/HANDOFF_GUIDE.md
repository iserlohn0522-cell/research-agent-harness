# 交接指南（换新对话）

Codex 与 Claude Code 共用。由 `{{GUIDES_DIR}}/AGENTS.md` 指向；只在写交接或从交接接手时读。

目的：让新对话读一页入口文件就能接着做，不必继承老对话的长上下文，也不必整份读大记录。

## 什么时候写

- 一个研究阶段结束、对话已经多次压缩上下文，或用户要求时。前两种情况先向用户提议换对话，用户同意再写。
- 平时不写“现状汇报”。决策、方法冻结、数据或分母的变化、负结果，在发生时就记进项目指定的记录；交接只做汇总，不替代这些记录。

## 写在哪里

- 每个项目只留一个总入口。按工作区规范（`{{GUIDES_DIR}}/WORKSPACE_STANDARD.md`）就是项目根目录的 `START_HERE.md`；还没按规范整理的旧项目沿用它原来的入口。交接时更新其中的当前状态，不新建 HANDOFF_V2 之类的竞争入口；旧内容靠 git 或月度记录留痕。入口链接的任务 README、结果页和运行状态页照常保留。
- 项目还没有入口文件时，按工作区规范建 `START_HERE.md`。

## 写什么（一页以内）

开头一行写交接日期、依据的最新记录，以及旧对话的链接（如有）。然后依次写：

1. 研究问题和当前决定。
2. 已确立的结论，附两三个决定性数字及其定义（分母、基线、样本群体或数据划分）。
3. 自上次交接以来变了什么：数据、样本量、分母或分组规则、方法。
4. 没解决的问题和下一步，下一步具体到第一件事做什么。
5. 不要重做的事：负结果和走不通的路，各用一句话说明原因。
6. 权威记录在哪里：给链接，不复制内容；大文件注明“按问题检索，不整份读”。

按 `{{GUIDES_DIR}}/REPLY_STYLE.md` 的要求写：说人话，内部代号要解释。事实要能在记录里找到依据，判断和建议标明是判断。

## 怎么接手

- 先读项目的 `AGENTS.md`（Codex 自动加载；Claude Code 靠项目 `CLAUDE.md` 里的 `@AGENTS.md` 加载，没有这一行就自己读）和入口文件。其他记录只在回答具体问题时打开，大文件按关键词检索。
- 入口文件的日期早于最新记录，或与记录冲突时，以记录为准，并向用户说明差异。
- 接手后的第一条回复，用两三句话复述当前决定和打算做的下一步，方便用户及时纠偏；没有冲突就不必停下来等确认。

## 老对话收尾

写完后告诉用户入口文件的完整路径，并给一句可以直接发给新对话的开场白，例如“从 D:/Projects/my-project/START_HERE.md 接手”。Codex 与 Claude Code 之间接力同样只靠这个文件；可以附上会话 ID 方便追溯，不需要共享完整对话。
