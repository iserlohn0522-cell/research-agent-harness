# 交接指南（换新对话）

Codex 与 Claude Code 共用。写交接或从交接接手时读。

目的：新对话读一页入口就能接着做，不必继承旧对话的长上下文。

## 什么时候写

- 研究阶段结束、对话已多次压缩上下文，或用户要求时。前两种情况先向用户提议换对话。
- 平时不写现状汇报。决策、方法、数据或分母的变化和负结果，在发生时记进项目记录；交接只做汇总。

## 写在哪里

每个项目只有一个入口：`START_HERE.md`（还没按工作区规范整理的旧项目沿用原入口）。交接时更新它，不另建竞争的入口文件。

## 写什么（一页以内）

开头一行写交接日期、依据的最新记录和旧对话 ID（如有）。然后依次写：

1. 研究问题和当前决定。
2. 已确立的结论，附两三个决定性数字及其定义（分母、基线、样本群体或数据划分）。
3. 自上次交接以来的变化：数据、样本量、分母或分组规则、方法。
4. 未解决的问题和下一步，具体到第一件事做什么。
5. 不要重做的事：负结果和走不通的路，各用一句话说明原因。
6. 权威记录在哪里：给链接，不复制内容；大文件注明按问题检索。

按回复风格写：说人话，内部代号要解释；事实能在记录里找到依据，判断标明是判断。

## 怎么接手

- 读项目 `AGENTS.md` 和入口文件；其他记录只在回答具体问题时打开，大文件按关键词检索。
- 入口早于最新记录或与之冲突时，以记录为准，并告诉用户差异。
- 第一条回复用两三句话复述当前决定和打算做的下一步，然后直接做，不停下等确认。

## 旧对话收尾

告诉用户入口文件的完整路径，并给一句可以直接发给新对话的开场白，例如“从 D:/Projects/my-project/START_HERE.md 接手”。
