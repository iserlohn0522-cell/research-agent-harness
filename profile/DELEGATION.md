# 委派指南

Codex 与 Claude Code 共用。`AGENTS.md` 只写原则；角色、派发、留档和自动任务的细节在这里，需要时再读。

## 什么时候派

子代理冷启动：开工前先读一遍平台的系统说明和工具定义（两万多 token，回一个“OK”也要这么多），回复还要回到主对话再读一遍。所以只有交给它的原始材料远多于它带回的结论时才划算：读很多文件或页面、翻长日志、大范围搜索、多步提取或实现。读一两个文件、跑一条短命令、确认一个值，主对话自己做。换便宜模型省的是单价，省不掉冷启动。

## 角色

作者的用法：主对话用最强的模型、中等推理强度，遇到难题时在会话里调高；子代理分三档。

| 角色 | Codex | Claude Code | 用途 |
|---|---|---|---|
| `luna_worker` | `gpt-6-luna`，推理强度按任务定：机械活 low，有边界的分析和实现 medium，较难的有界分析 high 或 xhigh | Sonnet，medium；纯机械活可指定 haiku，较难分析可指定 opus | 大量阅读、提取、实现、普通的独立核对 |
| `critical_reviewer` | `gpt-6-astra`，high | Opus，high | 主对话直接核对（重跑一个数、读原文）后仍定不下，或出错代价大又没法直接核对的关键判断 |
| `professional_reviewer` | `gpt-6-astra`，max | Opus，max | 极难且代价极高，或 `critical_reviewer` 定不下的问题 |

- 账户里没有表中的模型时，换成同档位的：小而快、主力、最强。
- Codex 里与主对话同模型的角色（两个评审）不采用角色文件的推理强度，而是跟随主对话，所以派发时写明推理强度（角色说明里也写了）。便宜模型做较重的实现不够用时，可以指定主力模型（如 `gpt-6-sol`）。
- `luna_worker` 做出的研究判断（例如结果是否有效、证据是否循环、样本是否合格）由主对话或 `critical_reviewer` 复核；抄数值、定位原文这类机械抽取可以直接用。

## 派发

- 先确认输入都在、事情还没做过。通常一次一个代理，两个子问题互相独立时才并行两个。
- 简报写清：具体问题和完成标准；必需的文件、证据和约束（Claude Code 子代理不读规则文件，项目约束要写进简报）；只读，还是可以改哪些文件；报告路径（当前任务文件夹的 `agents/`）和回复长度（约十行：结论、带出处的关键数字、未决问题、报告路径）。
- Codex 用 `fork_turns="none"`，由主对话自己组织上下文。独立评审只给证据和约束，不给期望的结论或其他评审的意见；要审查的主张标明“待审”。
- 续用已有代理只限紧接着追问同一个问题（例如“按你的意见改了，还有问题吗”）：续用要重读它的全部上下文，缓存过期后比新开还贵，评审还带着自己之前的结论。换问题就新开。
- 子代理不再派下级；超出范围的判断交回主对话决定。证据够了就停。

## 留档

- Codex 子代理把完整结果写进简报给的报告路径，回复只带摘要和路径。
- Claude Code 子代理把结果作为最后一条回复返回；主对话用 `python {{GUIDES_DIR}}/workspace-standard/workspace.py keep <任务文件夹> <主题> --claude-agent <agentId>` 把简报和回复存进 `agents/`。Codex 子代理没写文件时，同一命令用 `--codex-thread <线程号>` 取回它的最后回复。
- 主对话只复核决定性数字和有争议的地方；之后需要时读报告，不重新派发。一句话能说清的查询不留档。

## 自动任务

- 提示词约五句，只指向项目文件（方法、授权、进度记录），不复述规则、作业号或文件清单。
- 监控作业先在任务文件夹里写一个状态脚本：读进度记录，向调度系统查询一次未完成的作业，只输出一行 `NO_CHANGE`、`NOTHING_LEFT`，或列出每个已结束、失败或需要用户处理的作业。提示词只说：运行脚本；`NO_CHANGE` 时一句话结束，不读别的；其他情况按项目的方法和授权文件处理，并通知用户一次；`NOTHING_LEFT` 时停掉这个自动任务。
