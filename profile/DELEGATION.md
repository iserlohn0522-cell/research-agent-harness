# 子代理委派指南

Codex 与 Claude Code 共用。由 `{{GUIDES_DIR}}/AGENTS.md` 指向。当独立工作能明显减轻主对话的上下文负担或提供有价值的独立复核时，主代理委派，不需要为每次已在授权范围内的委派单独征求许可。

## 什么时候值得派

子代理是冷启动的：Codex 子代理开工前先读约 2.5 万 token 的系统说明、规则和工具说明，模型与主对话不同时还要更多；Claude Code 子代理实测同样约 2.4 万 token：约 1.6 万是自带的系统说明和工具定义；其余是规则文件和记忆索引。三个 Claude 子代理因此设了 `omitClaudeMd: true`，不读这些规则，项目约束由派发说明写清。它的回复还要回到主对话里再读一遍。所以省 token 的前提是：交给子代理的原始材料远多于它带回来的结论。

- 值得派：要读很多文件或页面、翻长日志、大范围搜索、多步提取或实现，而结果能压成几行加一个报告文件；两个互相独立的子问题可以并行；需要一个不受主对话思路影响的独立评审。
- 不值得派：读一两个文件、跑一条短命令、确认一个值、改几行代码。评审也一样：主对话直接核对（重跑一个数、读原文）能定的，不派评审；只有核对后仍定不下、或出错代价大又没法直接核对的关键判断才派。这些主代理直接做，比派子代理便宜。
- 便宜模型每个 token 比最强模型便宜，所以把大量阅读从主对话挪给 luna 仍可能省额度；但一件小事的冷启动成本本身就超过了事情本身，换便宜模型也省不回来。

## 选择角色

作者的用法：主对话用最强的模型、中等推理强度，遇到难题时在会话里调高；子代理分三档。

| 角色 | Codex | Claude Code | 合适的工作 |
| --- | --- | --- | --- |
| `luna_worker` | `gpt-6-luna`，推理强度按任务定：清点、提取、格式核对、日志摘要用 low；有边界的分析、实现、普通独立评审用 medium（角色默认）；较难的有界分析用 high 或 xhigh | Sonnet，medium；纯机械活可指定 haiku，较难的有界分析可指定 opus | 机械杂务，有边界的多步分析、实现、验证，普通独立评审（评审保持只读） |
| `critical_reviewer` | `gpt-6-astra`，high | Opus，high | 重大的研究或架构判断、关键假设和反例审查，或对卡住的推理问题做一次独立重读；只写自己的报告文件 |
| `professional_reviewer` | `gpt-6-astra`，max | Opus，max | 极难且出错代价很高的判断，或 `critical_reviewer` 解决不了的问题；只写自己的报告文件，按需使用 |

账户里没有表中的模型时，换成同档位的：小而快、主力、最强。

按判断难度和出错影响选择角色，按任务定推理强度。“独立”指独立分析证据，并不意味着每次都用最贵的档。`luna_worker` 做出的研究判断（例如结果是否有效、证据是否循环、样本是否合格）由主代理或 `critical_reviewer` 复核；抄数值、定位原文这类机械抽取可以直接委派。

角色定义的位置：Codex 在 `~/.codex/agents/*.toml`，以文件里的 `name` 字段识别；Claude Code 在 `~/.claude/agents/*.md`。在 Codex 里，派发时写明的模型和推理强度优先；角色文件的模型总会生效，但它的推理强度只在角色模型与主对话不同时生效，用同一模型的角色（两个评审）跟随主对话的推理强度。所以每次派发都写明推理强度：`luna_worker` 按任务定，`critical_reviewer` 写 high，`professional_reviewer` 写 max。未命名的通用子代理用 `[agents]` 的默认值，最好也显式写明。

## 主代理如何派任务

默认一次开一个代理；只有两个子问题互相独立时才并行两个。主代理马上能做完的小事直接做（见上一节）。不要为了多一轮评审而开代理，也不要把已经解决的问题交给新代理重复检查。

每次委派给出：

1. 一个具体问题和完成标准。
2. 必需的文件、证据片段、当前约束及尚不确定之处。
3. 只读，或明确的编辑范围；有多人工作时，要求保留他人的修改。
4. 报告路径：当前任务文件夹的 `agents/<日期-时间>-<角色>-<主题>.md`，以及简短的回复限制（约十行：结论、带出处的关键数字、未决问题、报告路径）。

子代理不继承主对话的全部上下文，由主代理单独给出足够完成子任务的材料。独立评审不接收主代理期待的结论或其他评审者的结论，但要拿到相关的原始证据和既定约束。需要审查的主张标为“待审查”，不要包装成已证实的事实。只针对子代理的规则（不读回复风格指南、不派下级、写报告文件）写在各角色文件里，子代理一定会加载。

## 结果留档

有实质内容的子代理结果和分支对话的消息都留在项目文件里：一是留档，二是主模型不必把长结果留在上下文里反复读。

- Codex：子代理自己把完整结果写进派发时给的报告路径（先写任务说明，再写结论和出处），给主代理的回复只有约十行和路径。评审角色与主对话权限相同，靠角色说明只写这份报告，不改其他文件。
- Claude Code：子代理不写报告文件，把结果作为最后一条回复返回，开头约十行是摘要。主代理用 `python {{GUIDES_DIR}}/workspace-standard/workspace.py keep <任务文件夹> <主题> --claude-agent <agentId>` 把任务说明和回复原文存进 `agents/`，不用重打一遍。Codex 子代理没按要求写文件时，同一命令用 `--codex-thread <线程号>` 取回它的最后回复。
- 主代理只复核关键数字和有争议的地方；任务 README 的结果部分链接用得上的报告。上下文压缩后、换新对话后或其他代理需要时，读报告文件，不重新派发。
- 一句话能说清的查询（找一个路径、确认一个值）不必留档。
- 分支对话和执行对话的消息同样先写进自己的任务文件夹，再发出带路径的摘要，见 `THREAD_SPLIT_GUIDE.md`。

委派的作用是把局部细节留在独立的上下文里，再把有来源的短结论带回主对话。主代理仍负责整合、核验和最终决定，不能把子代理的总结自动当成事实。

## 用量、停止与询问

- 同时最多两个子代理，通常一个。尽量复用已收集的证据；不为每个小步骤新开代理，但已有代理只用于同一任务的短续作，新的工作单元新开代理并给简短、独立的上下文。换便宜模型不会减少 token，上下文短才会。
- 续用已有代理：它的全部上下文每轮都要重读，隔久了缓存失效（Claude Code 子代理默认只缓存 5 分钟）会比新开还贵；评审续用还带着自己之前的结论。所以只在紧接着追问同一个问题时续用（例如“按你的意见改了，现在还有问题吗”），换问题就新开。
- 子代理不再创建下级代理。遇到任务边界或实质难题时，把已收集的证据和需要判断的事交回主代理，由主代理决定是否升级。
- 得到足够证据就停止；只有新证据、变化后的输入或尚未解决的实质失败，才值得追加工作。
- 保留阴性、失败、未命中和不确定的结果。检查通过、哈希一致或作业完成都不等于研究结论成立。
- 重要信息、方法、范围或授权缺失时，由主代理问用户。主动委派不扩大授权，也不替代外部写入、重大支出、破坏性操作或重启应用之前应有的批准。
