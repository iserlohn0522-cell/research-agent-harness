# 子代理委派指南

Codex 与 Claude Code 共用。由 `{{GUIDES_DIR}}/AGENTS.md` 指向。当独立工作可以减轻主对话的上下文负担、减少重复劳动或提供有价值的复核时，主代理主动委派，不需要为每次已在授权范围内的委派单独征求许可。

## 选择角色

| 角色 | 档位 | 合适的工作 |
| --- | --- | --- |
| `luna_clerk` | 小而快的模型，低推理强度 | 清点、提取、表格或格式一致性、日志摘要、按明确标准做机械复核 |
| `terra_worker` | 中档模型，中等推理强度 | 有边界的多步分析、实现、验证、普通独立评审；评审任务保持只读 |
| `critical_reviewer` | 最强的模型，中等推理强度 | 重大的研究或架构判断、关键假设和反例审查，或对卡住的推理问题做一次独立重读；只读 |
| `professional_reviewer` | 最强的模型，最高推理强度 | 极难且出错代价很高的判断，或中档评审解决不了的问题；只读，按需使用 |

按判断难度和出错影响选择角色。“独立”指独立分析证据，并不意味着每次都要用最贵的模型。`luna_clerk` 不负责需要实质判断的结论；普通复核优先交给 `terra_worker`。关键评审默认用 `critical_reviewer`，只有极难、出错代价很高或它解决不了的问题才升级到 `professional_reviewer`。便宜档代理做出的研究判断（例如结果是否有效、证据是否循环、样本是否合格）由主代理或 `critical_reviewer` 复核；抄数值、定位原文这类机械抽取可以直接委派。

角色定义的位置：

- Codex：`~/.codex/agents/*.toml`，以文件里的 `name` 字段识别角色；模型和推理强度写在文件里，按自己账户能用的模型设置。
- Claude Code：`~/.claude/agents/*.md`。`luna_clerk` 用 haiku，`terra_worker` 用 sonnet，`critical_reviewer` 用 opus；`professional_reviewer` 的活也交给 `critical_reviewer`。

## 主代理如何派任务

默认一次开一个代理；只有两个子问题互相独立时才并行两个。主代理马上能做完的小事直接做。不要为了多一轮评审而开代理，也不要把已经解决的问题交给新代理重复检查。

每次委派给出：

1. 一个具体问题和完成标准。
2. 必需的文件、证据片段、当前约束及尚不确定之处。
3. 只读，或明确的编辑范围；有多人工作时，要求保留他人的修改。
4. 简短的输出限制，通常是少量结论、精确来源和未决问题；需要产物时指明唯一的目标路径。正文、页面图片和大段提取结果留在文件里，只回报页码或行号和短引文；主代理只复核关键数字和有争议的地方。

子代理不继承主对话的全部上下文，由主代理单独给出足够完成子任务的材料。独立评审不接收主代理期待的结论或其他评审者的结论，但要拿到相关的原始证据和既定约束。需要审查的主张标为“待审查”，不要包装成已证实的事实。只针对子代理的规则（不读回复风格指南、不派下级）写在各角色文件里，子代理一定会加载。

使用命名角色时，以角色文件里的模型和推理强度为准；使用通用子代理时显式指定两者，避免继承主对话的高成本设置。

委派的作用是把局部细节留在独立的上下文里，再把有来源的短结论带回主对话。主代理仍负责整合、核验和最终决定，不能把子代理的总结自动当成事实。

## 用量、停止与询问

- 同时最多两个子代理，通常一个。尽量复用已收集的证据；不为每个小步骤新开代理，但已有代理只用于同一任务的短续作，新的工作单元新开代理并给简短、独立的上下文。换便宜模型不会减少 token，上下文短才会。
- 子代理不再创建下级代理。遇到任务边界或实质难题时，把已收集的证据和需要判断的事交回主代理，由主代理决定是否升级。
- 得到足够证据就停止；只有新证据、变化后的输入或尚未解决的实质失败，才值得追加工作。
- 保留阴性、失败、未命中和不确定的结果。检查通过、哈希一致或作业完成都不等于研究结论成立。
- 重要信息、方法、范围或授权缺失时，由主代理问用户。主动委派不扩大授权，也不替代外部写入、重大支出、破坏性操作或重启应用之前应有的批准。
