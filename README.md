# 科研 Agent 通用配置（Codex / Claude Code）

把 Codex 或 Claude Code 调成适合做科研的助手，不限领域。装好以后，它会：

- 用说人话的中文回复：先回答你问的问题，讲清结果意味着什么、为什么，不夸大；
- 按固定结构管理项目：每个项目有一页中文的接手入口，每件任务一个文件夹，每次改动记一条；
- 对话太长或一个阶段结束时，把现状交接给新对话，不再依赖老对话的长上下文；
- 按难度把子任务派给子代理：机械活交给便宜的模型，关键判断请最强的模型独立复核；
- 跑长实验时可以分两个对话：一个管研究主线，另一个一直做到“结果取回、核验过、可以解读”再汇报。

## 怎么装

1. 装好 Codex 或 Claude Code（两个都用也可以），各登录一次。
2. 把这个仓库下载到本地：`git clone` 仓库地址，或在 GitHub 页面点 Code → Download ZIP 再解压。
3. 在仓库文件夹里打开你的 agent，对它说：

   > 请阅读 INSTALL.md，帮我安装这个配置。

4. agent 会先看你电脑上已有的设置，问你几个问题（装给哪个工具、已有的全局规则怎么处理、回复用什么语言），列出要改的文件，你同意后才写入。被改动的文件都会先备份。
5. 技能不会自动安装。agent 会把 `skills/CATALOG.md` 里的清单念给你，你挑要哪些、装在全局还是某个项目里。

## 会改什么，不会改什么

- 会装：全局规则（Codex 的 `~/.codex/AGENTS.md`，Claude Code 的 `~/.claude/CLAUDE.md`）、几份指南、4 个 Codex 子代理角色和 3 个 Claude Code 子代理、工作区规范和它的小脚本。Codex 的配置文件里只加一行：最多同时开两个子代理。
- 不会动：操作前要不要你确认、沙箱和权限模式、模型和账号设置、你已有项目里的文件。这些都保持原样。

## 用起来是什么样

- **新项目**：在项目文件夹里说“按工作区规范初始化这个项目”。会生成 `AGENTS.md`（给 agent 读的项目规则，英文）、`START_HERE.md`（一页中文的接手入口）、`work/`（每件任务一个文件夹，名字带日期）和 `log/`（每月一份的改动记录）。已有的文件原地不动。
- **换新对话**：对话压缩过好几次，或一个阶段做完时，agent 会提议交接：把现状更新进 `START_HERE.md`，再给你一句开场白，发到新对话里就能接着做。
- **子代理**：清点、提取这类机械活交给 `luna_clerk`，有边界的分析和实现交给 `terra_worker`，重要判断请 `critical_reviewer` 独立复核，最难的问题才用 `professional_reviewer`。通常一次一个，最多同时两个，子代理不再往下派。
- **两个对话分工**：一个对话管研究主线，另一个负责执行。执行的对话一次做到终点才汇报，中途要你批准的事直接问你。项目里放一份授权书（模板是 `profile/AUTHORIZATION_TEMPLATE.md`），写明哪些事它可以自己做。

## 仓库里有什么

| 位置 | 内容 |
|---|---|
| `INSTALL.md` | 给 agent 看的安装步骤 |
| `profile/` | 全局规则、回复风格、交接、两个对话分工、子代理委派、授权书模板、工作区规范和脚本 |
| `codex/` | Codex 的 4 个子代理角色，以及要合并进配置的一行 |
| `claude/` | Claude Code 的全局规则（导入共享规则）和 3 个子代理 |
| `skills/` | 技能清单 `CATALOG.md`，以及自带的 draw.io 画图技能 |

给 agent 读的规则文件用英文，回复风格、交接等指南用中文。

## 更新和卸载

- 更新：下载新版本后，对 agent 说“按 INSTALL.md 的 Updating later 一节更新配置”。你改过的文件，它会先给你看差别再问你。
- 卸载：把安装时留下的 `.bak-日期时间` 备份改回原名，再删掉装上的文件。安装结束时 agent 会列出全部位置。

## 来源和许可

规则、指南和脚本整理自作者自己在用的配置，去掉了个人信息和专业限定。清单里的技能各属原作者，按各自的许可证使用，安装时从原作者的仓库获取。
